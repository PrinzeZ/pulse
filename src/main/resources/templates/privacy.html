Privacy Policy

Effective 1 October 2026. This policy describes how P.U.L.S.E handles account, inventory and security information. It is an application policy template and should be reviewed by the organization operating P.U.L.S.E before production deployment.

1. Information we process

P.U.L.S.E may process account names, usernames, roles, hospital/district/state scope, medicine inventory records, stock movements, request decisions, audit events and information required to operate the service securely.

2. Passwords

Passwords are not stored in plaintext. P.U.L.S.E uses password hashes for authentication. The authenticated Spring Security principal does not retain the password hash after authentication.

3. Hospital-local offline data

A hospital-local node may keep only the password hashes for authorized hospital administrators and hospital staff belonging to that configured hospital. State and district administrator credentials are not cached on the hospital node. Local credential authentication is additionally gated to loopback/private-network requests. Network location is a defense-in-depth control, not proof of identity.

4. Network information

P.U.L.S.E may process a client's network address transiently for brute-force protection and local-network security checks. The dynamic LAN routing feature can expose the currently registered private hospital LAN address to the P.U.L.S.E cloud endpoint so authorized clients can discover the local node. Private LAN addresses are not Internet-routable.

5. Cookies and browser storage

P.U.L.S.E uses essential session and CSRF cookies. It does not intentionally use advertising or analytics tracking cookies. A small browser preference may be stored to remember that the essential-cookie notice was seen.

6. Audit and retention

Stock movements and administrative decisions are retained in tamper-evident audit ledgers. Older records may be compressed and encrypted using the configured retention policy. The exact retention period must be aligned with the operating organization's legal and records-management requirements before production use.

7. Security

P.U.L.S.E applies authentication, role/resource authorization, CSRF protection, session hardening, security headers, brute-force controls, encrypted audit archives and Zero Trust principles. No security measure can guarantee absolute security.

8. Contact
